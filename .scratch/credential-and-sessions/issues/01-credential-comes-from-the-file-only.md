# 01: 凭据只来自文件，不再由配置播种

**What to build:** 守护进程启动时不再从配置项或环境变量读密码。凭据的唯一来源是凭据
文件里的 scrypt 哈希。

今天这两个来源还在：配置里的密码项、以及环境变量 `DSH_AUTH_PASS`。它们的用途是
「首次启动时把哈希写进文件」——也就是种子。这意味着系统里存在一份明文凭据，而它的
意义只是把一个值生成一次。这份副本没有任何存在理由。

移除之后，配置里设密码**不再有任何作用**。若某个部署仍然设置它，挂载时要明确说出来，
而不是静默忽略——否则运维会以为它还在生效。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 启动时不再读取配置项里的密码
- [ ] 启动时不再读取环境变量里的密码
- [ ] 凭据只来自凭据文件；文件里的哈希是唯一的比对依据
- [ ] 密码键从配置模式里移除
- [ ] 配置里残留这些键时，挂载给出明确提示说明它不再生效
- [ ] 系统里不再存在任何明文的凭据副本（配置、环境变量、日志都不留）
- [ ] 现有凭据文件的部署升级后仍能登录（不要求重新设置）
