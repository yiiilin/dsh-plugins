# 配对凭据自助管理与联邦会话总览

Status: ready-for-agent

## Problem Statement

守护进程的登录凭据是**一对**：本机一个密码，换一个会话。它现在是整个部署的
唯一入口，却只能靠改配置或删文件重启来更换——而这恰恰是最该随时能换的东西。

三处具体的困难：

**一、换凭据没有门。** 要改密码就得编辑 `cordis.patch.yml`，或者登录机器执行
`rm daemon/auth/pairing.json` 再重启。前者要求能 SSH，后者会让所有人都登不进来。
一个「怀疑密码泄露」的运维，手上没有一条安全的换法。

**二、装机路径依赖一个会被忘掉的东西。** 现在的设计里，配置项或环境变量里的密码
只是「首次启动时写进凭据文件的种子」。这意味着**系统里存在一份明文**，而它的存在
意义只是把哈希生成一次。种子一旦被删（或从未设置），启动就会失败——宁可起不来，
也不让人设置。对一个刚装好的机器，这是死路。

**三、看不到谁登录了。** 一个主节点下挂着若干边端，每一台上都可能有活跃会话。
运维没有一处能看到「现在有哪些浏览器以什么身份连着哪台机器、从哪个地址、
什么时候来的」。会话记录里这些信息都有，但只能靠读磁盘上的 JSON 文件。

## Solution

**凭据从「配置里的种子」变成「文件里的哈希」，并且能自己管。**

启动时不再读任何明文密码。凭据只以 scrypt 哈希存在凭据文件里。文件不存在时，
登录页变成「设置配对凭据」的引导，而不是启动失败。文件存在时，登录页只问那个凭据。

联邦网关面板从一个页面扩成三个分页：**环境、凭据、会话**。

- **凭据**分页里能改密码：填旧密码、新密码、确认。改完立刻生效，其他会话全部失效，
  自己这个保留。
- **会话**分页里能看到所有节点的活跃会话：客户端地址、客户端类型、最后活动时间、
  签发与过期时间、来自哪个节点。节点的查询并行发出，离线和慢的如实标注。

## User Stories

1. 作为运维，我想在界面上把配对凭据改掉，以便不必 SSH 到机器上改配置文件。
2. 作为运维，我想改密码时必须先输旧密码，以便我的电脑没有锁屏时别人改不掉它。
3. 作为运维，我想改密码后其他会话立刻失效，以便密码泄露时泄露的那一份不再有用。
4. 作为运维，我想改密码后自己保持登录，以便不用为了一次安全操作多登一次。
5. 作为运维，我想改密码时输两遍新密码，以便打错一个字不会把自己锁在外面。
6. 作为运维，我想在密码太短或者两次不一致时被挡住，以便规则拦在提交之前。
7. 作为运维，我不想在界面上看到任何形式的当前密码，以便它不会被拍照或记在草稿里。
8. 作为装机的人，我想在凭据文件不存在时看到设置密码的引导，以便新机器不用先改配置才能用。
9. 作为装机的人，我想引导页在任何能访问的地址上都可用，以便我在内网另一台机器上就能完成。
10. 作为运维，我想配置里不再需要写明文密码，以便系统里没有一份多余的凭据副本。
11. 作为运维，我想环境变量也不再是密码的来源，以便启动环境里无法留下凭据。
12. 作为运维，我想配置里如果还留着已废弃的密码项时被明确告知它不生效，以便不误以为它还在起作用。
13. 作为运维，我想看到主节点上有哪些会话，以便发现我没有发起的登录。
14. 作为运维，我想看到每个边端上有哪些会话，以便不用逐台登录去查。
15. 作为运维，我想每个会话显示客户端地址，以便判断登录来自我预期的位置。
16. 作为运维，我想每个会话显示客户端类型，以便认出是自己的浏览器还是一个脚本。
17. 作为运维，我想看到会话的最后活动时间，以便区分在用和已废弃的会话。
18. 作为运维，我想看到会话的签发时间和过期时间，以便知道它还能用多久、是什么时候批量出现的。
19. 作为运维，我想看到会话 id，以便和下发的日志里的标识对上。
20. 作为运维，我想看到每个会话属于哪个节点，以便知道该去哪一台机器处理。
21. 作为运维，我想离线节点被明确标注，以便不会把「查不到」当成「没有会话」。
22. 作为运维，我想某个节点响应慢时不拖住整张表，以便其余节点的信息照常可见。
23. 作为运维，我想一个节点查询失败时其余结果照常显示，以便单点故障不影响整体判断。
24. 作为运维，我想会话列表自动刷新或者能手动刷新，以便不必重开面板。
25. 作为运维，我想这个会话列表是只读的，以便它不会成为误踢自己下线的入口。

## Implementation Decisions

### 凭据不再由配置播种

- 启动时**不读**配置项与环境变量里的密码。密码只有一处来源：凭据文件里的 scrypt 哈希。
- 凭据文件不存在时，**不再启动失败**，而是让登录页进入「设置凭据」形态。
- 配置项与环境变量里的密码键从模式里移除；若某部署仍然设置它们，**在挂载时明确告知
  该项不生效**——静默忽略会让人以为它还在起作用。
- 移除的是「种子」这个概念本身，不是它的存储位置。系统里不应存在任何明文的凭据副本。

### 首次设置

- 判定条件只有一个：**凭据文件不存在**。不引入额外标记，不区分「首次安装」与
  「凭据被删」。
- 引导表单与登录表单是同一个页面的两种形态：一个输入框（设置）对两个输入框
  （设置 + 确认），还是原先的一个（登录）。两者互斥，由文件是否存在决定。
- **不限制来源地址。** 这是明确接受的取舍：文件不存在期间，任何能访问守护进程的人
  都可以设置凭据。它换来的是「内网任意机器都能完成装机」，代价是文件被删后的窗口期
  等于敞开。这一点要写在代码注释与模块文档里，不能只存在于设计记录中。
- 设置成功后直接进入已登录状态，不必再登录一次。

### 凭据修改

- 走一个需要已登录会话的管理端点，**并且必须校验当前凭据**。会话默认寿命很长，
  只凭会话就允许更换登录凭据，等于一次登录即可永久接管。
- 新凭据要求：非空、长度下限、两次输入一致。长度下限取 12 字符。
- 成功后**立刻**生效：写入文件、更新内存中的哈希、撤销其它会话。等重启生效会留下
  一个窗口，而这正是使用者更换凭据的动机所在。
- 撤销会话时**保留发起这次修改的那个会话**：它刚刚证明了同时知道新旧两个凭据，
  踢掉它只是多一次无意义的登录。其余会话一律失效。
- 界面上不显示凭据的任何信息——没有最后修改时间，没有掩码，没有提示片段。

### 会话总览

- 认证层新增一个只读的会话视图能力。它返回的字段集合就是展示需要的那些：
  标识、客户端地址、客户端类型、签发时间、最后活动时间、过期时间、是否当前会话。
  存储层已有的会话投影恰好覆盖这些，不需要新的投影。
- 主节点自己直接取；每个在线边端通过既有的隧道转发同一个只读端点，
  **并行发出**，不排队。
- 三种非正常情况必须如实呈现，不能与「零会话」混淆：
  - 节点离线：标注为离线，不给会话列表
  - 节点超时：标注超时，其余节点结果照常
  - 节点报错：标注错误信息，其余节点结果照常
- 单个节点的失败**不影响**其余节点。聚合结果是「部分成功」而不是全部失败。
- 本轮**只读**。撤销单个会话需要跨节点的写操作与失败回滚，不在本轮。

### 面板结构

- 联邦网关面板从单页面变为三个分页：环境、凭据、会话。默认停在环境。
- 分页状态只在当前面板会话内保存，不跨会话、不进 URL。
- 所有新增文案走既有双语字典，中英各一份。

### 版本

- 这是一次对外行为变更：配置里设密码不再生效，凭据可在界面更换。版本升到 `0.5.0`，
  模块文档写明升级路径。

## Testing Decisions

- **好的测试只断言外部可观察的行为。** 给定输入，观察结果——不发请求就不会去读源码
  文本的形状。本仓库里既有断言源码写法的测试（`assert.match(source, /.../)`），
  新增的测试不采用。
- **真实挂载优先。** 守护进程的入口、会话关卡、管理路由、面板都在同一条请求路径上，
  用真实挂载能把它们一起测到，且已有先例可循。
- **跨节点聚合用假 hub。** 隧道聚合中心提供「发请求」「是否在线」「列出环境」三样，
  注入它比启动第二个真实进程便宜得多，而且能确定性地制造超时与失败。
  真实双进程联邦留给人工验证。
- **要覆盖的行为**：
  1. 凭据文件不存在时，登录页是设置形态；提交后可用新凭据登录。
  2. 凭据文件存在时，登录页只问一个凭据，不出现设置形态。
  3. 修改凭据必须提供正确的当前凭据；错误的被拒绝。
  4. 新凭据过短或两次不一致时被拒绝，且凭据文件不被改动。
  5. 修改成功后，其它会话失效，发起者自己的会话仍有效。
  6. 会话列表包含客户端地址与客户端类型。
  7. 聚合结果里每个会话标注来源节点。
  8. 离线、超时、报错的节点各自以可区分的形式出现在结果里，其余节点不受影响。
  9. 配置里残留已废弃的密码键时，挂载给出明确提示。
- **先例**：`admin-prefix.test.js`（真实挂载 + HTTP 断言）、
  `auth-credential.test.js`（凭据存储与登录）、`auth-session.test.js`（会话生命周期）。

## Out of Scope

- **撤销单个会话**。列表只读。跨节点的写操作要处理失败与回滚，单独一轮。
- **凭据的重置流程**。凭据文件被删后由首次设置接管，不额外做「忘记密码」。
- **多用户**。仍然是单机单凭据。
- **会话列表的实时推送**。手动或进入页面时取一次即可，不做 WebSocket。
- **联邦接入凭据的管理界面**。环境接入 token 已有轮换端点，本轮不动。
- **`sessions.json` 的作用与内容**。它存的是已登录会话，与凭据文件无关，本轮不改。

## Further Notes

- **这一轮的核心取舍**：不限制首次设置的来源地址。它的收益是装机路径顺畅，
  代价是凭据文件被删后存在一个任何能访问者都可接管的窗口。这一条要在代码与文档里
  都写清，因为它是一个反直觉的默认值——通常的做法是收紧而不是放开。
- **凭据文件与会话文件是两件事**：前者存密码哈希，后者存谁登录着。删前者进入首次设置，
  删后者只是把所有人踢下线。两者都不该被误认为对方的备份。
- **与上一轮的关系**：上一轮把认证接口收窄到三个成员，这一轮要加回第四个（只读会话视图）。
  那不是回退——「谁登录着」属于认证层的职责，收窄时把它排除在外是因为当时没有调用者。
