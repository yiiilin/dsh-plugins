# 07: 收尾——旧会话失效与前缀修复

**What to build:** 两件收尾的事，各自独立可验证。

**旧会话一次性失效**：换凭据模型后，之前用通行密钥建立的会话不该继续有效——那等于
旧凭据还在生效。清空既有会话，浏览器需要重新配对一次。

**怎么失效**：删掉会话文件**没用**——进程还在时，下一次写入会把每条记录复活。
正确的机制是「撤销全部」：它清空内存里的会话表并立即落盘，旧 cookie 在下一个请求
就被拒，不需要重启。今天这个方法存在但从未被调用过。

**前缀修复**：`gateway` 的管理界面还有六处用根绝对路径拼请求。在带前缀的部署下
（主环境是 `/main/`，联邦环境是 `/env-<id>/`），这种路径会逃出前缀。

**今天会坏成什么样**：请求落到没有前缀的路由上，需要守护进程自己的会话 cookie，
而浏览器在 `/main/` 下配对时并没有那个 cookie——于是服务端回答 **200 + 登录页 HTML**。
客户端把 HTML 当 JSON 解析，失败被 try/catch 吞成「不可达」，面板只显示一个空列表，
控制台没有任何报错。（若部署恰好带着守护进程的 cookie，这六处能用——所以这是依赖部署形态的缺陷。）

**六处都在同一个辅助函数里**，所以修在辅助函数内部，一处改动全部修好。
去掉前导斜杠是关键：`/admin/state` 相对源解析会回到原点，重现 bug。

前缀解析**无法跨包共享**：每个插件包独立安装，client 半部必须自包含。
所以这次只修 `gateway` 这一处真实缺陷，其余包各自实现但保持同一种写法——
写法统一靠约定，不靠共享代码。
