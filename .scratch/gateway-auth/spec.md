# 认证模块加深与凭据模型替换

Status: ready-for-agent

## Problem Statement

守护进程的认证模块（`pkgs/gateway/lib/auth/`）目前是**一个浅模块**：

- 它的接口（`createAuth` 的返回值）几乎和实现一样大。接口暴露出 7 个成员，其中
  `sessions`、`passkeys`、`twoFactorEnabled`、`realm` 这四个**从未在模块外部被调用过一次**——
  它们是实现细节泄漏到了接口上。
- 它有 1488 行代码，**零测试覆盖**。测试全部绕开公开接口，直接 import 模块内部的纯函数去测；
  真正持有状态的部分（会话的增删改查、认证的完整流程）恰好没有测。
- 模块内部有约 200 行死代码：`policy.js`（111 行，一整套 host/origin 校验，无人引用）、
  `pwa.js` 的四个未用导出、`PasskeyStore.add()`（没有注册 passkey 的入口，方法从无调用点）。
- 凭据模型复杂而脆弱：用户名 + 密码 + TOTP + passkey 四种方式并存。密码为空时密码登录
  直接返回 403，此时**唯一可用的登录方式是预置的 passkey 文件**——而 passkey 无法注册，
  只能靠人工预置 `passkeys.json`。

同时，本仓库在别处已经出现过同一类问题的两个实例：

- `delete-session` 读取了一个 `SessionListState` 里并不存在的 `current` 字段，导致「当前那个
  空白会话」从列表里消失。已在本轮修好并带上回归测试。
- 四个 client 半部各自实现了一份前缀解析，其中 `gateway` 甚至还留着六处根绝对路径，
  已经漏修过一次。

使用者要的是：**一个接口小、能被测试的认证模块**，以及**一个不需要多个凭据方式就能配对的
简单模型**。

## Solution

把认证模块加深成一个真正的深模块：接口只留调用方真正需要的东西，其余收进实现内部；
删掉死代码并把 PWA 资源接上；补上从存储到 cookie 的测试覆盖。

凭据模型替换为单一的**配对凭据**——一个只用于把浏览器与这台机器配对的密码。它只做
一件事：换成一个会话。它不是 API 凭证，不与联邦的接入凭据混用。

登录页从「用户名 + 密码 + TOTP + passkey」简化为「只输一个配对凭据」。

## User Stories

1. 作为主节点的使用者，我想用一个配对凭据登录守护进程界面，以便不再需要维护用户名、
   TOTP 密钥与 passkey 三样东西。
2. 作为使用者的我，想让配对凭据只在本机有效，以便它泄露时不能被拿去调用别的接口。
3. 作为使用者的我，想让配对凭据只用于配对换取会话，以便它不会被当成长期有效的访问令牌。
4. 作为使用者的我，想在配对一次之后不必反复输入，以便日常使用不被反复打断。
5. 作为使用者的我，想让旧的 passkey 与 TOTP 路径消失，以便登录页不再有四条互相竞争的路径。
6. 作为使用者的我，想在配对凭据错误时收到清楚的中英文提示，以便知道是凭据不对而不是服务坏了。
7. 作为主节点的使用者，我想在忘记配对凭据时还有办法恢复，以便不被永久锁在外面。
8. 作为边缘节点的使用者，我想用同样的配对凭据方式访问我的环境，以便主边两端体验一致。
9. 作为开发者，我想让认证模块的接口只暴露真正被用到的东西，以便接口的每个成员都有存在理由。
10. 作为开发者，我想让会话存储与凭据校验的行为都有测试覆盖，以便改动时敢下手。
11. 作为开发者，我想让时间相关的行为（会话过期、空闲超时、cookie 续期）可以被确定性地测试，
    以便不用真的等。
12. 作为开发者，我想让测试不需要真的写文件到生产路径，以便测试互不干扰、可以并行。
13. 作为开发者，我想让存储的读写错误在启动时就暴露，而不是在第一个请求时。
14. 作为开发者，我想让认证模块的公开接口成为唯一的测试面，以便测试断言行为而不是实现细节。
15. 作为开发者，我想让死代码被删掉，以便读代码时不再需要分辨「这段还有用吗」。
16. 作为开发者，我想让 PWA 的 manifest 与 service worker 真的被服务，以便登录页的 PWA 声明
    不是一句指向 404 的话。
17. 作为开发者，我想让 gateway 的前缀解析与其他 client 半部一致，以便在带前缀的部署下
    面板不会空白。
18. 作为维护者，我想让「配对凭据」与「接入凭据」在术语表里分开，以便读文档时不会混称认证。
19. 作为维护者，我想让换凭据时旧会话一次性失效，以便旧的凭据不会继续有效。
20. 作为使用者，我想在改用配对凭据后不再需要维护通行密钥，以便只维护一样东西。

## Implementation Decisions

### 认证模块的接口

- 认证模块的公开接口只保留三个成员：处理认证端点与查询当前会话的方法、渲染登录页的方法。
  其余成员（会话存储实例、passkey 存储实例、双因素开关、realm 字符串）收进模块内部。
- 模块内部需要这些状态的地方直接用内部引用，不通过返回值再传出去。
- 删掉 `policy.js`：它的一整套 host/origin 校验从未被引用。删除前确认过它与
  `allowedOrigins` 等配置项无关——那些配置项本就不在当前 gateway 的配置模式里。
- `pwa.js` 保留真正被使用的导出；未用的四个删掉。同时把 PWA 资源真正接上：
  manifest 与 service worker 的路径此前在登录页里被引用，但没有任何路由去服务它们，
  请求一律 404。
- `PasskeyStore.add()` 删除——没有注册入口，它是一个永远走不到的方法。

### 凭据模型

- 引入**配对凭据**：一个密码，只用于用户验证。它把一个浏览器与这台机器配对，换成一个会话。
  它与联邦的**接入凭据**是两回事：接入凭据给机器看，配对凭据给人看，两者互不通用。
- 配对凭据以 scrypt 哈希加盐的形式存放在 DSH home 目录下的凭据文件里，权限 0600。
  凭据本体不落盘。用 Node 内置的 scrypt，不新增依赖——它同样是慢哈希、抗暴力破解。
- 彻底删除 passkey 与 TOTP：连同 passkey 存储、WebAuthn 依赖、双因素配置项、
  登录页的通行密钥按钮一起移除。登录页相应简化。
- **管理界面里其实没有通行密钥或双因素的代码**——勘察确认 `admin.js` 里零命中。
  原先写的「管理界面的相关操作」背后是空的，删的只是配置项与依赖。
- 因此不再做 passkey 注册入口，也不做已注册 passkey 的列表与删除——整条路径消失。
  预置的 passkey 文件也随之不再被读取。
- 换凭据模型时清空既有会话，浏览器需要重新配对一次。
- 实现顺序上，配对凭据先于删除 passkey：配对凭据不可用就删掉 passkey，会把人锁在外面。

### 会话身份

- 会话身份统一由「当前保留给主视图的会话」推导，与产品自身的做法一致。
  读取一个并不存在于会话列表状态里的字段，会让「当前那个空白会话」从列表里消失。
- **这条已经在 `delete-session` 修好，本次不再「抽到共用位置」。** 与前缀解析同理，
  client 半部必须自包含，跨包共享代码与仓库的包模型冲突。各包各自实现，写法靠约定统一。

### 前缀解析

- 前缀解析在多个 client 半部里各写一份，且已经漏修过一次（`gateway` 仍留着六处根绝对路径）。
- **它无法跨包共享**：每个插件包独立安装，client 半部必须自包含（`dsh.client.external`
  里只列 DSH 官方包，没有任何 yiln 包引用另一个 yiln 包）。因此不做「抽到共用位置」——
  那与仓库的包模型冲突。
- 本次只修 `gateway` 的六处根绝对路径，那是真实缺陷；其余包各自实现但保持同一种写法。
  写法统一靠约定，不靠共享代码。

### 依赖

- 删除 `@simplewebauthn/server`（仅 passkey 使用）。
- 不新增运行时依赖：scrypt 用 Node 内置的 `node:crypto`。

## Testing Decisions

- **什么样的测试是好的**：只测外部可观察的行为，不测实现细节。断言「给定这样的输入，
  观察到这样的结果」，而不是断言源码里长什么样。现有仓库里有若干测试在断言源码的字面写法
  （`assert.match(source, /.../)`），这类测试会在无关重构时误伤，本次新增的测试不采用这种写法。
- **三个测试层次**：
  1. **会话存储层**：创建、过期、空闲超时、cookie 续期、注销、持久化后重新加载。
     这一层已有干净的接缝——存储接受一个时钟函数与一个存储目录。
  2. **认证层**：带有效会话 cookie 的请求被接受，带无效 cookie 的请求被拒绝，
     cookie 格式不对的请求被拒绝。
  3. **配对凭据层**：正确的凭据被接受，错误的凭据被拒绝，凭据文件损坏时启动就报错
     而不是等到第一个请求。
- **切票**：见 `.scratch/gateway-auth/issues/`，七张票，按依赖顺序编号。
- **时钟与存储的替换**：`createAuth` 目前**没有**把时钟传给它内部创建的两个存储，
  所以现有的注入点够不到。需要让它转发——这是本次要补的一小步。
- **存储位置**：测试用临时目录，不碰生产路径。
- **既有先例**：仓库里已有测试用临时目录加可控时钟的写法（`delete-session` 与 `supervisor`
  的测试），照它们的路子。
- **死代码的删除由测试守住**：删掉 `policy.js` 之后，若有人再引入 host/origin 校验，
  不会有人记得那个文件曾经写过什么——这正是它该被删的原因。

## Out of Scope

- **不做多用户**。这套模型就是单机的，配对凭据不分用户。
- **不做 passkey 之外的第二因素**。TOTP 整体删除。
- **不改联邦的接入凭据机制**。那是另一件事，本次只保证它不被混淆。
- **不做 session 列表的产品级重写**。只修「当前会话」推导这一处事实，其余沿用产品既有逻辑。
- **不改 daemon 与 supervisor 的 systemd 单元管理**。那是另一处已识别的重复，不在本次范围。
- **不把 gateway 的 client 半部整体重写**。只修前缀解析这一处。

## Further Notes

- 换凭据模型会让既有会话一次性失效，浏览器需要重新配对一次。这是明确接受的代价。
- 当前部署用的是预置的通行密钥登录（密码为空，密码登录不可用）。删掉 passkey 路径之前，
  配对凭据必须先可用，否则会把自己锁在外面——实现顺序上，配对凭据先于删除 passkey。
  改完后需要用配对凭据重新配对一次浏览器。
- 登录页的表单从三块（用户名、密码、一次性码）变成一块（配对凭据），中英文文案同步调整；
  通行密钥按钮一并移除。

## 已知遗留（review 发现，本轮未处理）

- ~~cookie 续期机制没有生产调用者~~ **已解决**：`session()` 现在接受一个可选的响应对象，
  在 cookie 该续期时重发它。浏览器 cookie 的 `Max-Age` 原本在登录时算一次，
  而服务端截止时间随活动滑动——活跃用户会在原始窗口关闭时被要求重新配对，
  那是会话本身从未到达的截止点。续期阈值是动态的（已用时间的 1/3 等于原寿命的 1/4）。
- **`pnpm-lock.yaml` 陈旧**：仍列着五个已不存在的包目录，且没有 `pkgs/gateway` 的 importer。
  `npm run check` 与 `npm test` 都不读它，所以不影响验证，但它与磁盘现状不符。
- **历史文档仍提 passkey/TOTP**：`docs/changes/*` 与 `docs/verifications/*` 里还有引用。
  它们是历史记录，不是当前说明。
