# DeepSWE 题面效果评测

这里仅保存可复用的题目和校验标准。运行 collective-deliberation 的效果评测前读取本文件；委员会执行步骤遵循 [SKILL.md](../SKILL.md)。

- `cases.json`：六道题的压缩题面、选项、原始题源链接、仓库与 base commit。
- `answers.json`：按题目 ID 索引的离线校验标准；`valid` 是正确选项，`serious` 是严重错误选项，`unsupported` 是缺乏题面支持的选项，`proof` 是判定依据。这两个错误集合可以重叠。

## 运行与文件位置

1. 每次评测创建 `/tmp/.collective-deliberation-<uuid>/`。多题评测为每题分别创建委员会 run 目录，评测汇总也写入独立的同前缀临时目录。
2. 仅把当前题的 `cases.json` 条目交给主席，再由主席分发给委员。答案键、历史结果与校验报告只供评测者使用，讨论、投票和摘要阶段均不读取；这是行为约束，不代表宿主文件隔离。
3. 委员提案使用 skill 的 JSON 字段，并在 `title` 中标注所判断的选项 ID。保持原选项 ID 和文本，冻结提交方式与选项到结果的映射后再运行；映射记录写入 run 目录。
4. manifest、题面快照、映射、模型执行记录、重试记录、委员 JSON、combine JSON/Markdown、CSV、final result、摘要和评测报告全部写到 `/tmp/.collective-deliberation-<uuid>/`。评测期间项目及本目录只读；不在 `evals/` 下创建 `runs/`、缓存或报告。
5. 委员会最终结果冻结后，评测者读取答案键并独立校验，将校验输入、规则、结果及失败记录写入临时目录。校验不回写或调整委员会票数、均值与状态。

## 校验口径

- 逐题记录最终接受的选项集合，并与 `valid` 做集合全等比较；全等才算该题完全正确，同时报告漏选、误选、`serious` 和 `unsupported` 命中。
- 接受集合的产生规则必须在运行前冻结。例如只接受被明确判断为成立且状态为 `candidate` 的选项；`needs_review` 不计为接受。同一选项有多个结论时，提前定义聚合规则，不能看过答案后择取结论。
- 执行失败或无法可靠映射选项时记录为失败/不可判定，单独报告完成率，不能静默剔除或算作正确。评测汇总保留全部六题的状态。
- 这些材料评测需求理解和边界判断，不是官方 DeepSWE 代码修复成功率，也不替代官方 verifier。六题答案布局一致，可能产生位置偏差；若随机打乱选项，提前生成并保存可重放映射，以原选项 ID 校验，不能覆盖源题库。

历史一次性运行数据不随题库恢复；新的效果评测继续使用新的临时目录。
