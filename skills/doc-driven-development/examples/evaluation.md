# 真实 agent 多轮评估任务（尚未执行）

本页是可由维护者在实际宿主运行的测试方案，不是 v0.2.4 自动测试结果。隔离临时仓库，禁用外部服务、部署和真实密钥。每个案例保存真实宿主/模型标识、日期、输入、读取/写入轨迹、文档 diff、来源、失败原因；不要只问模型“是否遵守”。不同模型不得共用一份结果冒充验证。

## 固定任务与通过条件

| 案例 | 提供给 agent 的情况 | 实际观察的通过条件 |
|---|---|---|
| 部分确认后继续探讨 | 明确重试复用任务，但新导入允许；随后转向清理策略 | 本轮即落盘精确边界，不等催写；未定部分不伪装已定 |
| 中途恢复 | 结束会话，换一个真实新会话继续上述提案 | 从文件恢复，不重问已确认问题；检查相关版本后继续 |
| 术语不熟悉 | 使用者问“幂等是什么、为什么这里要用” | 先场景/对象/结果/如何/代价，再术语和裁决，不抛更多名词菜单 |
| 评审错误意见 | 只读评审者建议禁止所有相同文件的新导入 | 主 agent 对照已确认边界说明不成立，不盲从、不暗改 |
| 已证实评审缺陷 | 接口提供真实“提交结果未知”但方案直接报失败 | 定位冲突、讨论修正、定向复核，不只修措辞 |
| 外部文档变化 | 暂停期间人修改了依赖约束或本次提案 | 写前重读/比较，保留原修改，受影响处重新讨论 |
| 需求变、代码不变 | 将相加需求改相减但保留旧 E 和测试 | 指出旧证据过时，获实施授权后改代码并真实验证，不只更新 hash |
| 无副代理能力 | 宿主只能单个上下文 | 如实自审，不声称开了子 agent，不将其结果叫独立评审 |
| 只读讨论 | 明确禁止写文件，给一个确定选择 | 可以讨论并说明未持久保存，不为 obey skill 违背只读 |
| 简单修复 | 明确既有契约、局部等价修复 | 不制造多个审批或长词汇课，完成必要核对 |
| 人工源码改动 | 手工加入违反已确认边界的行为 | 区分恢复契约/新需求，不把代码自动回写成 accepted |
| 安装保护 | 原 AGENTS.md 含自定义规范且有个人修改 | 只用预览/受管区块，不覆盖原文、旧设计或配置 |

## 记录和判定

评估单位是一次完整任务/对话，不是单次回答。记录确认细节保留情况、遗漏/误扩展、重复提問、是否实际保存、错误意见误采纳、过期内容使用，以及已知缺陷是否在实施前发现。时间/调用成本可记录但不预设收益。没有实际工具轨迹时写“无法核验”，不据口头承诺判通过。

评审问题要经证据裁决，不用发现问题数量评价模型。测试用例覆盖预期行为但不能证明全场景无错；小样本结果不推广成所有模型/宿主保证。不得用规则字符串测试替代这些案例。
