# 人读得懂的讨论、文档和交付

编号是机器定位手段，不是用户界面。讨论及交付首先回答：在哪个领域、哪个功能/模块、哪个行为；原问题是什么；现在怎样了；用户能做什么；有什么没完成；哪些下一步已经会继续做，哪些确需用户选择。

## 术语和图服务于场景

按“何时发生 → 上下文 → 想得到什么 → 怎么做 → 代价 → 真正要决定什么”解释。先说“超时后再次提交不能创建第二个任务”，再补充这个机制叫幂等，不先问“要不要幂等键”。事实由 AI 调查；重要行为和取舍交给使用者；局部实现自主。

涉及顺序用 ASCII 流程图，涉及生命周期用状态图，涉及组件数据交换用数据流图，涉及同一时刻的不同参与者可用 ASCII 时序图。选择能解释当前困惑的视图，不为每个简单答复画三张。图后用两三句解释箭头条件、数据归属、异常去向，未知留白说明，不画出未经确认的实现。

```text
[用户重复提交] --同一请求标识--> [查询已有任务]
                                     |
                                     +--存在--> [返回原进度]
                                     +--不存在--> [按并发安全规则创建]
```

这张图解决“重复提交怎么处理”；标识如何保存、冲突如何裁决需要在对应详细设计核对，不能把图当正确性证明。

## 稳定标识在机器层，标题与导航用自然名称

保留 Doc-ID、R/C/D/E 的稳定身份，不删除或重排。新正文使用：

```markdown
### 请求超时后再次提交
<!-- ddd:item R-IMPORT-003 -->
同一次提交带原请求标识重试，复用已有任务，不创建重复导入。
```

旧 `### R-IMPORT-003 请求超时后再次提交` 仍有效。R、C、D、E 均支持同一隐藏标记，须紧随真实标题（中间只能空行），不能藏在代码块、多行注释或证据正文伪造定义。只要旧标题的自然文字不变，单纯把编号移至标记，契约指纹保持不变；实质正文修改仍会失效。结构检查可能提示重新检查标题/链接，这是正常的定位核对，不能借此伪造重新测试。

**改可见标题会改变 Markdown 自动锚点。**在获准的格式整理范围，先查实际入链及渲染器，保留可用的旧显式锚点或修复入链，再核对导航；不能只批量正则去编号。安装/升级不做这次迁移，通用链接检查也不验证所有标题锚点。无权改历史文档时只改善报告称呼，不改文件。

元数据和详细证据可以放在文档尾部独立证据小节或受工具支持的折叠呈现中；Doc-ID 等头字段仍保留在解析器约定的位置。不要为隐藏字段新建第二套事实副本。不把 Spec-Refs/哈希表复制进正文说明。

索引以“领域 / 自然标题”显示；查找支持 `context.mjs --query "恢复提示词" --human`，机器仍用 JSON/ID 定位。不同模块重名时显示领域和实际路径消歧，不要求用户记编号。

## 交付报告结构：结果先于活动，阻塞先于细枝末节

默认顺序：总体可用性结论 → 按自然名称列已完成的用户行为与实际验证 → 未完成行为及对用户的影响 → 下一步（直接继续或唯一需要人决定的问题）。命令、路径、编号、版本指纹放按需展开的技术附录或链接。没有用户决策就明确“本轮没有新增决策需要你确认”，不要编造“仍需要你的”清单。

不要用“B3 已补 21 条 E、错误从 6 类到 4 类”充当功能结果；这仅是维护活动。不要只说“已实现”后在括号里承认消费者不存在。尚缺运行路径时，第一句就说尚不能端到端使用。测试计数说明必测场景实际运行范围，不仅总数。

不要把一般架构偏好写成必然真理，例如“业务规则绝不能在 SQL”不是本 skill 的规则。应结合事务一致性、并发、查询成本、接口复用与测试解释取舍。

## 对用户提供记录的表达示例（未核验其业务仓库）

下面只根据用户摘录重组，不将自述当独立验证，也不捏造命名和入口能力：

> **恢复提示词仍未端到端接通；消息派发和系统配置已有实现进展，但整体验收尚未完成。**
>
> **消息派发 / 后台循环：**记录称此前只有接口，现在接入正式后台循环，并补充重试需要的消息内容；尚无覆盖这条正式派发路径的专用端到端验证，因此不能宣布整条功能已验证。
>
> **系统配置 / 参数持久化：**记录称七个参数已写入数据库并设置合法值约束，在新数据库运行了相关检查。这支持这部分配置检查，不代表整个系统可交付。
>
> **会话恢复 / 提示词传递：**记录称映射和一次性注入逻辑已经实现，但缺少把提示词送入目标子进程的接口。因此当前用户仍无法通过这条链路获得完整恢复提示。先查既有授权和接口设计；若接线已在范围内就补齐，只有新增接口行为/权限需要讨论时才提出具体选择。
>
> **维护活动：**已回填文档状态与证据，但不能据此推导产品可用性。关于磁盘清理，需另核对资源所有权和删除授权；“匿名卷”不是安全删除依据。

报告的目的不是删掉诚实的限制，而是让限制与用户影响出现在正确位置。技术细节仍可追溯，不淹没结论。
