- 只读预览、执行必须匹配预览指纹；design-only/hold/disabled 不能运行；无效计划/未知字段/范围漏项拒绝；持续授权不等于新增生产权限。

- Node 原生 suite 和命名用例解析；空测试文件的 Node file-wrapper pass 不算执行了行为用例。正常 JSON、当前 run nonce、严格 flat TAP；嵌套/不完整/多计划/重复/未知 TAP 拒绝。
- 具体可选跳过有理由且不影响必测时披露；可选项实际失败仍失败。静态命令无伪造测试计数，不能代替 acceptance。manual 保持待人工，不伪造签字。
- 环境缺失、输入/工具缺失、依赖失败阻塞；无关检查继续。真实进程超时、输出上限、锁竞争、符号链接输出拒绝；参数中的 shell 元字符不被隐式执行。
- 规格正文/修订、代码、测试、配置、计划、规则和显式忽略输入变化使旧记录失效；运行中修改被标 stale。嵌套 Claude 规则单独绑定。
- 实际日志被改、校验失配、篡改计数与原始输出不符、错误 run nonce 和另一个计划的记录被拒绝。即使校验可重算，也明确本地 unsigned 记录不提供恶意篡改防护。
- 环境只按名称显式转发，未指定秘密不继承；明文、分块汇总及 JSON 转义后的已知环境值在持久日志/结果中脱敏。不声称这构成完整 DLP。
- runner-v1 严格交付拒绝手写 passed；真实记录输出的 E 可满足当前规格/代码交付；移除 profile 绕过检查被拒绝。错误 Runner-Check/缺失 runs 拒绝；同一次实际运行可显式支持两个验证层但不冒充两次独立运行。

## 3. 可复现的真实运行演示

包内 [examples/verification-demo.mjs](examples/verification-demo.mjs) 在显式指定的全新目录生成一个隔离项目。实际运行并断言：

```text
组件存在 + 正式入口断开 -> 场景测试失败
接通实际入口           -> 同一场景真实通过
更改规格但保留旧记录   -> 旧记录校验失败
SKIP + 进程 exit 0      -> 仍判定失败
恢复并重新执行         -> 生成新通过记录，保留全部旧运行
```

```sh
node examples/verification-demo.mjs --run --out /actual/new/directory
```

演示和测试使用合成规格/授权夹具；它们确实执行本地代码，但不声称任何真实用户批准、消息派发/会话恢复业务已实现，或真实模型已经遵守规则。

## 5. 尚未验证和信任边界

没有真实用户业务项目、真实宿主/模型 API、实际子 agent、跨模型长会话、费用/时长对照，也未在 Windows/macOS 或其他 Node.js 版本实测。示例 eval-suite 是可执行的起步材料，实际 real-host 试验与主观轨迹审阅仍未运行。

已执行的事实是本地子进程与它产生的报告；没有证明断言充分、需求完整、人的批准真实、数据库/远程服务状态不变，或恶意脚本无法篡改产物。本地哈希不是签名，参数数组启动不是沙箱；Windows 的后代进程清理尤其需要外部隔离。工具不会认证手工验收，也没有“强行转绿”选项。

支持原生 Node reporter、规范化 JSON 和有限 flat TAP，不保证任意测试框架输出可被解析。大仓性能、隐藏依赖发现、全部敏感内容脱敏不在实测保证内。真实交付仍结合受保护 CI、对验收/测试变更的审阅，以及用户场景核对。详细边界见 [VERIFICATION.md](VERIFICATION.md) 和 [EVALUATION.md](EVALUATION.md)。
