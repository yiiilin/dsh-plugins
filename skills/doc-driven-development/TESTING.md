## 启用链路的回归

[tests/activation.mjs](tests/activation.mjs) 检查：不再导出公开 config-only 初始化接口；旧 init 文件名转发完整安装器；默认预览零写入且 setupComplete 为 false；显式 apply 后必须具备包、规则、配置/索引、收据并通过 doctor。仅有 enabled=true、只复制 skill、缺入口、缺收据、过时版本、未完成锁均不能报告 ready。

覆盖现存 init-only 项目、已禁用配置、本地受管区块/包修改、无变化重装、安装过程中故障回滚、配置最后提交，以及实际运行状态不被静态检查冒充。原工作流测试中旧 init 测试已改为验证兼容转发，而非继续接受仅配置初始化。

## 领域布局的回归

[tests/layout.mjs](tests/layout.mjs) 检查默认落点为 `docs/domains/<domain>/features/` 与 `docs/domains/<domain>/modules/`，并拒绝 domain 策略下的根部 features/modules、扁平领域规格、缺领域层、Type 与目录错配。验证中文领域名、多个文档根、跨领域引用、生成索引、全量进度与合法领域路径协作；历史规格和不必要的空目录不被强制迁移。

已有配置缺 layout 按 preserve 读取而不改原 JSON；已有受管功能/模块但没有配置时，首次接入选择 preserve。安装参数不能覆盖旧配置。对于用户报告的“领域摘要 + 根部功能/模块”，preserve 给出差异，domain 文档检查失败，二者均不移动文件或放宽策略。doctor 的文档布局结果与静态安装状态分开，不能靠重装修正文档目录。

目录检查仅验证受管当前规格的路径形状；未带 Doc-ID 的历史正文、业务领域是否合理、模型是否理解正确，均不由这些测试证明。模板与入口一致性也设有回归断言，避免根部示例再次成为默认。

## 安装与原文保护

[tests/install.mjs](tests/install.mjs) 覆盖默认只读预览、显式 apply、宿主入口选择、重复安装/升级/卸载、归属哈希、备份日志、文件和路径冲突、嵌套与覆盖规则提示。

原文保留测试包含中文、UTF-8 BOM、LF/CRLF/混合换行、无末尾换行、空文件、区块前后个人内容、索引外导航、原 JSON 字节及普通权限。边界外原文不被重新格式化。

反例包含本地修改的受管区块、不完整/重复/反向标记、围栏中的标记、未闭合 Markdown 结构、无效编码、UTF-16、大文件、只读文件、符号链接、硬链接、目录占位、越界路径、安装锁与个人文件冲突。故障注入验证写前变化拒绝、部分写入回滚，以及回滚不能覆盖后来发生的个人修改；不模拟所有并发或断电状态。

[tests/run.mjs](tests/run.mjs) 保留规格字段、审批/证据、归属、代码基线、索引、渐进与全量覆盖检查，并运行一个隔离的可执行示例。用于边界测试的审批、阅读与测试证据明确是夹具，不是真实业务记录。

## 使用真实上一版发行文件的端到端试验

在临时目录解开本会话的 v0.2.1 ZIP，实际运行该旧版 init：它生成 enabled=true 的配置/索引，但没有项目 skill 与规则区块，复现报告状态。然后用 v0.2.2 的 doctor → install 预览 → apply → doctor → 已安装包自检 → 无变化重装 → 追加个人规范 → 卸载。

检查预览零写入、修复前 incomplete、修复后 ready、runtime 仍 not-run、原配置逐字节保留、已有规则原文前缀保留、已有设计正文及业务源码不变。重复安装零修改；卸载恢复未改的原文并保留后追加规则。

另外用真实 v0.2.1 受管安装升级、真实 v0.2.0/v0.2.1 未受管目录接管；不以自造哈希替代这些迁移来源。遇到旧规则不完整或已安装 skill 被本地改动时拒绝且不写入。试验使用的是旧技能包的真实文件，而不是用户真实业务仓库。

## 重现与归档

```sh
node scripts/check.mjs
node --test tests/run.mjs tests/install.mjs tests/activation.mjs tests/layout.mjs
```

第一条核对包清单、元数据、链接、语法并运行全部四组测试。发行 ZIP/TGZ 在解包后再次执行同一自检，两份归档逐文件 SHA-256 核对一致；归档校验值随发行包提供。

## 未验证与局限

未在 Windows/macOS、其他 Node.js 版本或真实 AI 宿主、多模型长期项目上实测；换行/路径夹具不等于跨平台认证。静态通过不证明模型已自动加载、不会越界、真实批准、命令实际执行或业务正确。

安装与目录诊断不自动搬迁设计，不实施 CI/宿主写权限门禁。备份和回滚不是跨文件断电级事务；中断后按 INSTALL 的日志与文件基线核对，不能盲目用备份覆盖新修改。哈希是完整性检查，不是可信签名或防篡改审批平台。仍在使用旧全局 v0.2.1 的 agent 不会被新压缩包远程更新，必须使用新包入口或通过所在工具正常更新技能来源。
