# 可选多 agent 与成本模式

这是跨宿主工作协议，不包含模型 API、密钥、自动选模型、收费服务或后台调度器。先检查当前宿主实际可用的委托、模型选择、并行、权限和上下文能力。没有子 agent 时单 agent 顺序执行同样边界，明确实际模式；不能假称已派发独立评审或换用了便宜模型。

## 两种组织都支持，但职责只有一套

模式一：主 agent 兼任设计主持者，强模型集中处理用户讨论、规格和跨模块风险；执行任务用适合的 worker。

```text
[使用者] <--> [主 agent：规格、授权、验收责任]
                         |
             +-----------+-------------+
             v           v             v
          [开发]      [测试]       [只读评审]
             +-----------+-------------+
                         v
                [主 agent：集成核对]
```

模式二：常驻主 agent 负责轻量协调，按需委托强模型的设计主持者；不让昂贵模型持续读取所有日志。

```text
[使用者] <--> [协调主 agent：唯一对话/任务调度]
                         |
             +-----------+----------------+
             v                            v
 [强模型设计主持者：需求/边界]      [开发/测试/评审 workers]
             |                            |
             +--版本化任务约定------------+
                         |
                         v
           [指定集成人：核对最终装配和证据]
                         |
                         v
                  [协调主 agent 报告]
```

第二种模式中，设计主持者可以是子 agent，但不必再让它递归派发孙 agent：协调主 agent 可直接派发执行者。用户说的两种模式不要求不同程序框架，只改变哪个角色常驻。宿主支持再委托时也必须显式设置深度和预算，默认不递归。子 agent 不能扩大用户权限或批准业务变化。

**文档只有一个主写入者**，可以是强设计主持者；协调者只保存明确的工作状态，不同时改契约。开发 worker 只改分配路径，提交建议而不私自修订需求；评审 worker 默认只读。设计主持者失效时先保存版本化移交，再更换写入者。技术验收可委托，最终范围声明与对用户责任仍由指定主 agent 负责；不要让廉价协调者不查证就复述“通过”。

## 委托边界

每次派发复用已有提案内的交付单元，传递最小充分上下文：自然名称和用户结果；准确规格修订/条目及关键原文入口；真实实施授权；允许写入路径/禁止修改；状态、接口及不变量；前置依赖；入口接线责任；测试与环境；交付物和停止条件；预算/重试边界。不要只发“实现 C2”，也不要无差别复制整库历史。

worker 开始前回读当前相关原文，对比指纹；发现规格变更返回主持者，不能用老快照执行。先复述完成标准及是否具备前提，这是一项执行核对，不是再次向用户请求同一批准。

返回内容：实际 diff/提交位置、自然名称下实现了什么、还缺什么、实际命令与非空产物、必测 executed/skipped/failed、规格和代码身份、受阻原因、真实资源消耗。不能只返回“done”。集成人查证 diff/工件；合并后检查当前代码与运行入口，不把分支通过当最终集成通过。

## 并行和成本纪律

只并行无文件冲突且接口边界稳定的工作。耦合任务先定接口/启动链再串行或分批；同一路径多个写入者必须分离工作树并指定合并者，创建工作树也要有权限。无法隔离则排队，不并发覆盖。外部服务、数据库和 Docker 资源同样需要独立命名/所有权/清理预算。

不承诺多 agent 必然省钱。主 agent 思考、worker 上下文、复核、失败重试、工具与环境成本都计入总成本。高风险复杂实现可直接使用强模型，不以低价牺牲正确性。没有模型选择权限时记录真实能力，不能将“建议角色”当“已切换模型”。

开始时读取项目已有预算/授权；未给额度不编造美元上限。默认单层委托、最少必要 worker，能由确定性脚本完成的检查不另开模型。同一失败不得无界重试；按约定的尝试次数/调用预算停止升级处理。并行度、最大委托深度、返工次数、上下文规模都属于任务边界，超过已知限制先缩小并行或回报。

先选典型任务对照单 agent：比较端到端实际费用、完成时长、漏项/回归、用户重复确认次数、返工次数和真正完成的行为数量；不能只比较 worker token 单价。宿主不提供账单或 token 数时写未测量，不报告“节省了 X%”。工程依据和适用限制见 [ENGINEERING.md](ENGINEERING.md)。

## 可直接复用的委托开场

给开发 worker：

> 实现“领域 / 模块 / 行为”这一交付单元。先读所列当前规格和已有授权；只改指定路径，不改变需求、接口或权限边界。按验收场景实现并接入约定入口，真实运行可用检查。发现范围内遗漏自行补齐；新重要设计选择或权限缺口只向协调者报告，不擅自找用户重新确认既定事项。返回 diff、实际运行及跳过、证据路径、未完成影响和资源消耗。不要修改主规格、审批字段或其他 worker 文件。

给设计主持者：

> 你负责本次规格的单一写入与边界维护，不是独立授权者。读取原任务和已确认决定，找真正新增的逻辑缺口，用场景和适用 ASCII 图解释；每次明确决定及时保存。输出可分工的行为单元、必守约束、上下文版本、接线责任、验收与风险。已有批准不重新审批；收到 worker 偏差时查证后决定范围内修复或提交新增取舍，不照单全收评审意见。

给验收/评审 worker：

> 默认只读，核对最终集成代码而不只看作者总结。逐项按用户行为验证实际入口/消费者、状态与数据流、异常和已授权代码差异。测试缺前提或被跳过就如实报告；每个问题给位置、具体反例和影响，不凑数量。区分已证实缺陷、待调查与可选改进，不能改文档或预期来让测试通过，也不能替用户批准未定方案。


## v0.3 的执行与采证责任

设计主持者维护验收场景和命名必测；执行者不能改预期以制造成功。测试 worker 在明确资源/权限内使用 verify 执行，返回真实 run.json 及校验引用，不只返回自填计数。集成人在最终版本运行/复核必需检查，工作树不同或计划/测试变化要重新判断，不把分支记录直接升级成合并后证明。

同一工作树的验证串行，避免争用数据库和覆盖产物；不同工作树也需要外部资源隔离。对子 agent 默认只授予相应写路径，不授予 grader、验收门禁、生产秘密或全局清理能力。强模型负责语义评审和新增取舍，确定性采证由脚本完成，减少重复粘贴长日志。真实费用只能经 [EVALUATION.md](EVALUATION.md) 的宿主试验比较，fixture 不证明省钱。
