# 版本记录

## 0.2.0 — 2026-09-18

基于用户提供的 0.1.0 原始压缩包重构，不是对该项目代码做了逆向分析。

### 保留

保留先讨论再实现的确认关口、关键选择的推荐与代价、归属路径/接口名称、已有目录兼容、机械检查和原作者/第三方许可。

### 改变

- 从逐项转录转为遵守已确认需求和关键设计约束；允许明确边界内的实现自由。
- 功能文档按需求、概要、关键详细设计分层；共享模块独立，当前规格与本次提案区分。
- 将观察、获批、实现和验证区分；代码优先不自动批准所有新选择。
- 项目显式启用，不按目录形状误触发；不再将特定宿主的发现目录、描述截断等当作通用规则。
- 源码指针可选；普通 JSON、配置、测试和既有代码不必为了接管被批量插注释。
- 新增渐进接管、全量范围盘点、代码快照、按文件记录的阅读进度和可恢复批次。
- 提供安全初始化、盘点、生成索引、文档结构检查、变更范围门禁及自测；无第三方运行依赖。

### 清理

删除 skill 自己的四份长期设计/验证文档及重复生命周期说明，不再让使用者读一套“skill 的 skill 文档”；以单份使用说明、参考和场景替代。

删除强制词汇表及 `_Avoid_` 同义词约束、单独决策点格式、每个前提必须单独验证文件、按包一刀切、所有复杂函数伪代码化、索引状态手工复制、强制源文件反向指针、对其他 skill 的隐含依赖。

原始发行包中的试点估计和历史验证结论不移植为本版已验证效果。新增脚本测试检查可执行行为，不代表完成了跨模型长期真实项目试点。

### 旧项目迁移

不自动覆盖旧文档或批量修改代码。先运行新初始化（已有文件会保留），调整 `.doc-driven.json` 的 `docsRoots` 和 `index`，再逐篇接管需要维护的文档。

旧 `draft` / `awaiting confirmation` 对目标文档映射为 `proposed`；逆向现状应为 `observed`。旧 `confirmed` 只有能找到真实确认记录才映射为 `accepted`。旧 `implemented` 必须拆查确认、实现和验证，不能无证据直接映成 `accepted + complete + passed`。旧 `superseded by ...` 分为 `Status: superseded` 与 `Superseded by`。

旧 `Version: vN` 改为 `Revision: N`；增加唯一 `Doc-ID`、`Type` 和 `Baseline`。`Owns` / `Owns names` 可以保留；已有源码 `doc:` 指针不必删除。未迁移文档不会被默认为新格式，但检查会提示发现的旧头部。
