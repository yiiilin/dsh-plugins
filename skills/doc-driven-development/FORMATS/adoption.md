# 接管报告模板

全量基线需要，渐进接管可只保留简短范围与下一步。路径可适配已有布局。进度 JSON 的精确格式见 [ADOPTION.md](../ADOPTION.md)。

```markdown
# 项目设计恢复记录

Doc-ID: ADOPTION-PROJECT
Type: adoption
Revision: 1
Status: observed
Baseline: unknown
Owns: —
Implementation: not-applicable
Verification: not-run

## 目标与范围
模式：渐进 / 全量。
本次仅记录现状，不修改业务代码。
纳入路径、主要功能边界、排除项及理由；已有文档如何映射。
按领域列出功能/模块真实落点；新布局为 domains/<domain>/features/、domains/<domain>/modules/，旧布局迁移需独立授权。

## 代码基线与盘点
实际 Git 提交/工作树情况、inventory 快照。
候选、已读、部分、受阻、明确排除的数量，分母写清。
文件映射覆盖不等于语义理解或正确性。

## 阅读导航
先读概要设计，再读各功能/共享模块，最后看风险和验证记录。

## 分批进度
| 范围 | 实际已读文件/入口 | 产出文档 | 当前状态 | 待解事项 |
|---|---|---|---|---|

## 跨模块核对
接口、数据归属、异常传播、鉴权、迁移/发布等适用的关键检查。

## 未知、冲突和疑似缺陷
事实、推断、待确认意图分开。标注影响与证据，不顺手重构。

## 已执行验证
实际命令/步骤、环境、版本、结果、不能验证的内容。

## 本次交付与继续入口
明确已完成和未完成范围；下一批从哪个入口继续。
全量未结束时不得写“全项目分析完成”。
```

## 讨论与图的补充要求

每批报告按主题列出：已查明事实、缺失/矛盾、调查依据、影响、建议讨论的问题和下一步。实际控制/数据/状态图在对应功能或模块，不在接管报告复制全套。未知分支如实标注；无关问题不阻塞其余分析。全量覆盖完成不等于批准这些历史行为。
