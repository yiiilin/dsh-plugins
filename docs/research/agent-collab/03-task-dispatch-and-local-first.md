# AI agent 协作平台：任务派发与本地优先调研

> 资料截止口径：2026-02。只采用项目官方文档、官方 GitHub/GitLab README/源码和协议；访问日为 2026-09，访问日之后出现的状态变化不倒推到截止日。功能断言来自官方当前主分支；无法用截至日历史快照证明的日期敏感项标为“截止日未查证”，不把它们当作历史活跃度结论。“无官方证据”不等于功能绝对不存在。
>
> 记号：D=人派任务与状态机/依赖/优先级/认领拒绝转派；C=agent 协商分工；A/N=文件产物/通知；I=任意外部 tool-calling AI 接入；O=部署、license、活跃度。

## 总览

- 没有查到一个开源项目同时提供“人建群/邀请任意 agent、可认领/拒绝/转派的任务看板、agent 自行协商、文件与通知、纯本地两机运行”。现有项目分别覆盖：编码 agent 工作区（Vibe Kanban、Claude Squad、OpenHands）、编排原语（LangGraph、CrewAI）、工作流/HITL（n8n、Dify、Flowise）、消息/传输（Matrix、Nostr、libp2p、Hypercore、CRDT）。
- 最接近产品语义的是 **CrewAI + MetaGPT**（可委派或按角色协作，但成员和角色由代码预先定义），以及 **NIP-17/NIP-29 + 自建任务层**（群组/邀请/消息/文件协议较接近，但没有任务语义）。没有证据表明它们支持任意 agent 运行时自建群并拉入陌生 agent。
- 纯本地 MVP 应把“任务事件/状态机/租约”与“agent runtime”分离：本地 SQLite/事件日志 + LangGraph interrupt + OpenHands ACP/CLI 适配器；两机共享黑板用 Automerge Repo 或 Yjs，网络层用 libp2p/Hyperswarm。Matrix/Nostr 适合作为通知/聊天网关，不应直接当任务状态机。

## 1. 任务看板、编码 agent 与相近编排

- **Vibe Kanban**：D=人创建、优先级和分配 Kanban issue，再启动带分支/终端/开发服务器的 workspace；未见 agent 认领、拒绝或转派 API。C=多个编码 agent 是隔离 workspace，并非 agent 间协商。A/N=git diff、inline review、PR/merge；通知主要在 UI/GitHub，未见通用推送。I=支持 Claude Code、Codex、Gemini CLI、Copilot、Amp、Cursor 等已列出的 CLI/集成，不是任意 agent 成员协议。O=`npx`/本地或自托管；Apache-2.0；截至日活跃度未回溯，访问时 README 另标注“sunsetting”（后续状态，不用于 2026-02 结论）。来源：[README](https://github.com/BloopAI/vibe-kanban#readme)、[LICENSE](https://github.com/BloopAI/vibe-kanban/blob/main/LICENSE)。
- **Claude Squad**：D=人以 prompt 建立 session；session 有运行/暂停/删除/恢复等生命周期，但无看板字段、依赖、优先级或 agent claim/refuse/reassign。C=无 agent 间协商，只有每个 session 独立运行。A/N=tmux、git worktree、分支、diff、commit/push；TUI 状态，无独立通知总线。I=`-p` 可运行本机 Claude/Codex/Gemini/Aider 或其他命令，需 CLI 适配。O=本地终端+tmux+`gh`；AGPL-3.0；CI/release 信号存在，截止日活跃度未量化。来源：[README](https://github.com/smtg-ai/claude-squad#readme)、[LICENSE](https://github.com/smtg-ai/claude-squad/blob/main/LICENSE.md)。
- **OpenHands Agent Canvas / Software Agent SDK**：D=对话、GitHub issue/automation/webhook/schedule 可派发和追踪运行；Agent Server 有持久 conversation/event，但不是带优先级和认领的共享看板，未见 agent 拒绝/转派协议。C=可接多个 agent backend，官方描述“自动把 issue 分解为 tasks”，但未见运行时 agent 自主谈判。A=本地/容器/VM workspace、文件、diff、报告、PR；N=Slack、GitHub、Datadog/webhook 等 automation。I=可接 OpenHands、Claude Code、Codex、Gemini 或 ACP-compatible agent；任意 tool-calling AI 仍需 ACP/Agent Server adapter。O=本地 npm、Docker、远程 Agent Server、自托管；MIT；README 标 beta，截止日活跃度未回溯。来源：[OpenHands README](https://github.com/OpenHands/OpenHands#readme)、[SDK README](https://github.com/OpenHands/software-agent-sdk#readme)、[ACP agents](https://docs.openhands.dev/openhands/usage/agent-canvas/acp-agents)。
- **Magentic-UI / MagenticLite**：D=人通过 UI 输入大任务，系统在关键动作前暂停；可 steer/approve/take over，但没有任务 board、依赖、优先级或 agent claim/refuse/reassign。C=编排器与浏览器使用模型是内部协作，不是可邀请的 agent 群。A=浏览器和本地文件系统操作产物；N=UI approval/check-in，无通用通知总线。I=连接配置的模型 endpoint；不接受任意外部 agent 作为成员。O=本地 `uv`/`magentic-ui`（README 说明 macOS/WSL）、MIT；主线已从旧 0.1 分支演进，截止日活跃度未查证。来源：[README](https://github.com/microsoft/Magentic-UI#readme)、[配置](https://github.com/microsoft/Magentic-UI/blob/main/docs/configuration.md)。
- **TaskWeaver**：D=自然语言任务由 Planner 分解并跟踪进度，有角色/插件上下文和代码执行状态；未见通用任务优先级、agent 自认领/拒绝/转派状态机。C=Planner、CodeInterpreter、Recepta 等角色和 shared memory 协作，属于框架内角色编排。A=Python 代码、DataFrame、图表和 output 文件；N=CLI/WebUI/stream/log，未见跨渠道通知。I=Python library、LLM 配置和 plugin API，外部任意 tool-calling agent 需自己封装。O=Python/Docker/本地容器执行；MIT；README 有 2025 新闻，截止日活跃度中等但未量化。来源：[README](https://github.com/microsoft/TaskWeaver#readme)、[memory](https://microsoft.github.io/TaskWeaver/docs/memory)、[Docker](https://microsoft.github.io/TaskWeaver/docs/usage/docker)。
- **AutoGen（相近同类）**：D=AgentChat `run(task=...)`、Team/GraphFlow 由代码定义，状态主要是消息与终止条件，无内建优先级/依赖看板或 claim/refuse/reassign。C=`AgentTool`、team patterns、human-in-the-loop 可委派；成员仍由应用创建。A=Workbench/MCP 工具结果、消息流和应用自管文件；N=Console/event stream。I=需 Python AgentChat/工具接口或 MCP adapter，不是任意 agent 即插即用。O=本地 Python/AutoGen Studio；官方 README 标为 maintenance mode，License 文件为 CC BY 4.0；截止日活跃度低/维护。来源：[README](https://github.com/microsoft/autogen#readme)、[AgentChat docs](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/index.html)。
- **MetaGPT（相近同类）**：D=一行需求进入固定 SOP，角色产出阶段性结果；无共享任务看板、优先级、认领拒绝转派。C=产品经理/架构师/项目经理/工程师按“软件公司”角色协作，不是运行时自由组群。A=用户故事、需求、API、文档和代码仓库；N=CLI/日志，未见通用通知。I=Python/LLM 配置和角色 API，需 SDK 封装。O=本地 Python/CLI；MIT；README 有 2025 发布新闻，截止日活跃度未量化。来源：[README](https://github.com/geekan/MetaGPT#readme)。

## 2. 任务生命周期与人工协作原语

- **HumanLayer / Agent Inbox**：旧开源仓库 README 明确说代码“pretty much all deprecated”；当前官网描述 multiplayer coding-agent workspace、session/plan artifact/diff 和 remote daemon，但未验证现行开源 Agent Inbox 的任务状态机、agent claim/refuse/reassign 或开放协议。旧仓库 Apache-2.0；截至日活跃度应按 deprecated 处理。来源：[旧 README](https://github.com/humanlayer/humanlayer#readme)、[当前官网](https://humanlayer.dev/)、[当前 docs](https://docs.humanlayer.com)。
- **LangGraph interrupt/HITL**：D=应用以 StateGraph 的节点/边定义任务，checkpointer 保存状态；`interrupt()` 暂停，`Command(resume=...)` 恢复，`thread_id` 是持久游标，可自建依赖/优先级/claim 事件。C=子图、工具调用、Command 跳转由应用实现，非内建协商。A=JSON state、checkpoint 和外部文件；N=`stream_events`/interrupt 投影，渠道需自行接。I=框架级 API，任意 tool-calling AI 需实现模型/工具接口。O=Python/JS、本地或部署；MIT；官方持续维护。来源：[README](https://github.com/langchain-ai/langgraph#readme)、[Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)。
- **CrewAI human input**：D=`Task` 有 agent、`context` 依赖、顺序/层级 process、async、`human_input`、guardrail、output_file；无 UI 看板和 agent claim/refuse 状态。C=`allow_delegation=True` 自动提供 delegate work/ask question，层级 manager 可分工；成员/角色仍由代码配置。A=文件、JSON/Pydantic/Markdown、guardrail 输出；N=callback/日志及外部 Flow/集成。I=需 CrewAI Agent/Task/Tool/LLM SDK，不能让任意外部 agent直接入组。O=Python/本地或 AMP；MIT；官方 docs/README 活跃。来源：[Tasks](https://docs.crewai.com/en/concepts/tasks.md)、[Collaboration](https://docs.crewai.com/en/concepts/collaboration.md)、[README](https://github.com/crewAIInc/crewAI#readme)。

## 3. 工作流平台：多 agent、审批、文件、通知

- **n8n**：D=画布节点/连接是依赖与执行状态，webhook/chat/trigger 派发；无跨 workflow 任务优先级、agent claim/refuse/reassign。C=AI Agent 可把另一个 Agent/Workflow 当 tool，属于显式嵌套而非自主组群。A=Binary/file 节点和 workflow JSON；N=HITL 支持 Chat、Slack、Discord、Telegram、Teams、Gmail、WhatsApp、Google Chat、Outlook，approve/deny。I=多模型与 1500+ integrations，但外部 agent 需 API/MCP/Workflow Tool 接入。O=自托管 Docker 或 Cloud；Sustainable Use License + Enterprise License（source-available，非普通 OSI OSS）；官方持续维护。来源：[README](https://github.com/n8n-io/n8n#readme)、[HITL tools](https://docs.n8n.io/build/integrate-ai/ai-examples/human-in-the-loop-for-tools.md)。
- **Dify**：D=Workflow 图节点提供依赖/分支；Human Input 可 web/email 请求表单、Approve/Reject 等 action、timeout branch，未见 agent claim/refuse/reassign。C=Agent/Workflow 节点可串联或嵌套，未见官方“自由组群/协商分工”协议。A=RAG 文档、Agent sandbox 文件；Human Input 支持文件字段。N=web app、email、Service API；超时可接通知/重试。I=支持 OpenAI-compatible models、MCP、REST API，但外部 agent 是调用方，不是成员。O=Docker Compose、Cloud、企业版；Dify Open Source License（Apache-2.0 基础加附加条件）；官方 docs 版本历史未锁定，截止日活跃度未查证。来源：[README](https://github.com/langgenius/dify#readme)、[Human Input](https://docs.dify.ai/en/cloud/use-dify/nodes/human-input.md)。
- **Flowise**：D=Agentflow 图和递归/最大迭代；官方 multi-agent 是单 Supervisor 顺序一次一个 task，未见优先级/claim/refuse/reassign。C=Supervisor 根据 `{team_members}` 把任务派给固定 Worker，再聚合结果；Human Input 节点可 approve/reject/feedback loop。A=节点/工具结果、表单及外部文件节点；N=HITL 是流程暂停，不是通用通知总线。I=需 function-calling Chat Model/Flowise API，外部 agent 通过 API 调用而非加入。O=Node/Docker/self-host；README 访问时已标 archived（后续状态，不回填 2026-02）；Apache-2.0，enterprise 目录商业许可。来源：[README](https://github.com/FlowiseAI/Flowise#readme)、[Multi-Agents](https://docs.flowiseai.com/using-flowise/agentflowv1/multi-agents.md)、[Human in the Loop](https://docs.flowiseai.com/tutorials/human-in-the-loop.md)。
- **Langflow**：D=可视 flow graph 有节点依赖/运行结果，没有任务看板或 agent claim/refuse/reassign。C=README 宣称 multi-agent orchestration/conversation management，具体仍是 flow/component 编排。A=文件组件、flow JSON/API 结果；N=Human-in-the-loop/组件和自建 webhook，未见统一通知服务。I=每个 flow 可作 API 或 MCP server；外部 tool-calling agent 可调它的工具/flow，但需 MCP/API adapter。O=本地 Python、Docker、Desktop；MIT；官方 README/发布信号活跃，截止日未量化。来源：[README](https://github.com/langflow-ai/langflow#readme)、[MCP server](https://docs.langflow.org/mcp-server)、[HITL（版本页）](https://docs.langflow.org/1.11.0/human-in-the-loop)。
- **Coze Studio**：D=可视化创建/发布 Agent、App、Workflow，API 可启动 conversation/chat；没有官方证据证明任务状态机、依赖优先级或 agent claim/refuse/reassign。C=Agent+Workflow+Plugin 是资源组合，未见自由 agent 群协商。A=知识库、插件、数据库、Prompt、工作流数据和上传器；N=Chat SDK/API/第三方集成，未见 agent 组内通知原语。I=Community API 与 Chat SDK，外部 agent 需 API/SDK 适配。O=Docker Compose、自托管；Apache-2.0；截止日活跃度未查证。来源：[README](https://github.com/coze-dev/coze-studio#readme)、[API/SDK wiki](https://github.com/coze-dev/coze-studio/wiki/6.-API-Reference)。
- **FastGPT**：D=Flow、Agent Skill、用户交互节点可编排，未见共享任务状态机、优先级、claim/refuse/reassign。C=可做工作流/插件/MCP 组合，未见 agent team 协商。A=知识库支持 TXT/MD/HTML/PDF/Docx/PPTX/CSV/XLSX 等，Flow/MCP/API 可产出结果。N=对话记录、运营日志及自接渠道；无通用组通知。I=OpenAPI、MCP、plugin 可被外部 agent 调用，但不是成员协议。O=Docker/Cloud；FastGPT Open Source License（Apache-2.0 加禁止相似多租户 SaaS、不得去 Logo/版权等条件）；活跃度截止日未量化。来源：[README](https://github.com/labring/FastGPT#readme)、[文档](https://doc.fastgpt.io/guide/getting-started)。

## 4. 本地优先与去中心化传输

- **Matrix Conduit**：D/C=Matrix server 本身不定义任务、优先级、claim 或协商；A=Matrix event/media/file APIs；N=客户端同步、房间事件、已读/typing/presence（Conduit README 说明部分联邦功能仍缺）。I=任何 Matrix Client-Server bot/客户端可加入，tool-calling AI 需 Matrix adapter。O=Rust 单 binary、内置数据库、Apache-2.0、Beta。两机可各自运行 homeserver 并联邦，或一台自托管 homeserver 给另一台客户端；不是无服务器直连。来源：[Conduit README](https://gitlab.com/famedly/conduit/-/blob/next/README.md)、[官网](https://conduit.rs/)、[Matrix spec](https://spec.matrix.org/latest/)。
- **Nostr（NIP-17/28/29/94）**：D/C=协议只定义事件/群/消息，没有任务状态机或 agent 协商。A=NIP-17 多人加密 room、NIP-29 relay-based closed group、NIP-94 文件元数据。N=NIP-01 relay subscription/`NOTICE`/实时 event。I=agent 用 keypair+Nostr client/bot adapter；不存在“任意 tool-calling AI 自动入组”。O=自建 relay 或使用多个 relay；NIPs public domain。两机可无中心服务商地运行自建 relay/组，但 NIP-29 的群 enforcement 仍绑定 relay，不是纯 client-to-client。来源：[NIP-01](https://github.com/nostr-protocol/nips/blob/master/01.md)、[NIP-17](https://github.com/nostr-protocol/nips/blob/master/17.md)、[NIP-29](https://github.com/nostr-protocol/nips/blob/master/29.md)、[NIP-94](https://github.com/nostr-protocol/nips/blob/master/94.md)。
- **Holepunch Hypercore / Hyperswarm / Pear**：D/C=安全 append-only log、topic discovery 和加密连接，不定义 task/协商。A=Hypercore blocks/log 可承载文件、事件和状态；N=应用在 Hyperswarm connection/stream 上自定义。I=任意 agent 需使用 JS/Pear 或自定义协议 adapter。O=Hypercore/Hyperswarm npm、Pear 跨平台；Hypercore/Hyperswarm MIT，Pear Apache-2.0。两机可经 HyperDHT topic 发现后直连，仍依赖 DHT bootstrap/NAT 条件；没有中心应用服务器。来源：[Hypercore](https://github.com/holepunchto/hypercore#readme)、[Hyperswarm](https://github.com/holepunchto/hyperswarm#readme)、[Pear](https://github.com/holepunchto/pear#readme)。
- **Yjs / y-webrtc**：D/C=CRDT shared Map/Array 与 awareness，不是任务/协商层。A=共享文档、离线更新、快照；N=awareness/peer events。I=任意 AI 需 JS Yjs adapter，把 tool call 写入共享文档。O=Yjs/y-webrtc MIT；两机可 WebRTC P2P，但 y-webrtc README 明确 peer discovery 通过 signaling server，服务器可自托管，故不是零基础设施。来源：[Yjs](https://github.com/yjs/yjs#readme)、[y-webrtc](https://github.com/yjs/y-webrtc/blob/master/README.md)。
- **Automerge Repo**：D/C=CRDT documents、Repo/DocHandle 事件和 pluggable network/storage，不定义 task lifecycle 或 agent negotiation。A=本地 IndexedDB/NodeFS、可 export/import 的文档；N=change/document events。I=JS/TS SDK，外部 agent 需接 Repo 或自定义 network adapter。O=MIT；两机需 WebSocket/自定义网络 adapter（默认没有跨机器直连），可无中心地运行但要自行提供 discovery/transport。来源：[README](https://github.com/automerge/automerge-repo#readme)、[核心包](https://github.com/automerge/automerge-repo/blob/main/packages/automerge-repo/README.md)。
- **libp2p**：D/C=网络协议栈，不提供任务/文件/agent 协商；A=应用自定义 protocol stream；N=PubSub/GossipSub。I=任何 agent 可通过自定义 protocol/MCP bridge 接入，但需实现身份、消息和权限。O=多语言实现；js-libp2p 同时 MIT/Apache-2.0，specs 不是完整产品 license。两机局域网可用 mDNS/已知 multiaddr，跨 NAT 通常需 DHT/bootstrap/relay；不是开箱即用群组。来源：[specs README](https://github.com/libp2p/specs#readme)、[js-libp2p README](https://github.com/libp2p/js-libp2p#readme)。

## 5. 记忆、共享 blackboard 与 agent groups

- **Letta**：D=消息、schedule、subagent 可做分解/并行，但不是人可拖拽的 task board；无内建 claim/refuse/reassign。C=官方有 specialized subagents；未见自由邀请外部 agent 协商。A=MemFS、工具和文件；Shared memory 是组织拥有的 Git repo，可挂给多个 cloud agents，官方明确 local agents 使用自己的 MemFS。N=Slack/Telegram/Discord/Signal/custom channels。I=Agent SDK、App Server、ACP；任意 agent 需 adapter。O=本地 CLI/Desktop、self-host App Server 或 Cloud；当前源代码在 `letta-ai/letta-code`，Apache-2.0；截止日活跃度未回溯。来源：[历史仓库 README](https://github.com/letta-ai/letta#readme)、[Shared memory](https://docs.letta.com/concepts/shared-memory/index.md)、[Subagents](https://docs.letta.com/configuration/subagents/index.md)。
- **Mem0**：D/C=不是编排器；提供 User/Session/Agent memory 的 add/search/update API，不定义任务认领、协商或 blackboard 冲突规则。A=结构化/向量记忆，不是共享文件产物；N=无内建通知。I=Python/JS SDK、API，需在每个 agent runtime 中集成并自行用 `agent_id`/`user_id` 等隔离。O=library、Docker self-host server 或 Cloud；Apache-2.0；README 有 commit-activity/SDK 维护信号，截止日未量化。来源：[README](https://github.com/mem0ai/mem0#readme)、[官方 docs](https://docs.mem0.ai/introduction)。
- **Blackboard 结论**：TaskWeaver shared memory、Letta shared-memory repo、Yjs/Automerge CRDT 都能承载“共享上下文/任务文档”，但没有一个官方实现同时给出可竞争 claim、租约、拒绝、转派、依赖和审批。应把 blackboard 当共享数据层，把任务状态机另建为事件/状态投影；来源：[TaskWeaver memory](https://microsoft.github.io/TaskWeaver/docs/memory)、[Letta shared memory](https://docs.letta.com/concepts/shared-memory/index.md)、[Yjs](https://github.com/yjs/yjs#readme)。

### 最接近“agent 自建群、拉人、协商”

1. **CrewAI**：官方 collaboration 原语直接提供 delegate work/ask question，hierarchical manager 能动态分工；但 agents、角色和 crew 由开发者预先创建，没有群邀请、能力发现、拒绝/转派状态机。[官方 collaboration](https://docs.crewai.com/en/concepts/collaboration.md)
2. **MetaGPT**：官方“software company”把多个角色组织为 SOP，产出链条和文件最接近工作小组；但角色固定、无运行时拉人/谈判/看板。[官方 README](https://github.com/geekan/MetaGPT#readme)
3. **协议补足而非完整答案**：NIP-17/NIP-29 已有多人 room、closed group、join/invite/admin 和消息；配合 NIP-94 文件事件可补“群通信”，但必须另建任务状态机与 agent capability/negotiation 层。

## 7. 纯本地 MVP 形态

- **控制面**：一个本地进程维护 `group/member/task/task_event/artifact/approval`；任务状态先定为 `queued -> claimed -> running -> blocked/review -> done|failed|cancelled`，事件中记录 `priority`、`depends_on`、`lease_until`、`claim/reject/reassign` 和幂等 key。
- **agent 接入**：本地 OpenHands SDK/ACP、Claude/Codex/Aider CLI 和任意 HTTP tool-calling AI 都通过统一 adapter；adapter 只需收发 `task.offer/accept/reject/progress/result`，不要求模型采用某一 SDK。
- **协商**：先做显式 blackboard 协议：agent 发布能力/报价/预计耗时，调度器按依赖和租约选中；后续才让 planner/manager agent 生成分工，所有决定仍落事件日志，避免仅靠聊天文本。
- **共享数据**：单机用 SQLite + 本地 content-addressed artifact；两机用 Automerge Repo 或 Yjs 复制任务/成员/事件，文件用哈希清单和分片传输；CRDT 只解决合并，不替代权限、租约和审批。
- **两机无中心**：局域网优先用 libp2p mDNS/已知 peer；跨网用 Hyperswarm/libp2p DHT/relay。若需要可读群聊，再加 Conduit 或 Nostr relay；这些组件都不是任务调度器。
- **人工协作与通知**：敏感 tool call 走 LangGraph `interrupt()`；本地 WebSocket/SSE 显示状态，Matrix/Nostr/邮件作为可选通知桥。最小部署是两台机器各一进程、互换 peer 公钥、无云账号；若使用 Yjs WebRTC，仍需自托管 signaling。
