# ADR 0002 — 环境以 helper 为单位

## 状态

已接受（2026-10-18）。

## 背景

「一个远程环境」需要一个身份，用来：在注册表里索引、在远端 `authorized_keys` 里标记
它那行公钥、在删除时精确清理、避免两个环境共享同一个可执行文件。

候选身份有两种：以**主机**为单位（一台机器一个环境），或以**helper**为单位
（一个 helper 一个环境）。

## 决定

**环境以 helper 为单位。** 身份键是 `(sshHost, sshHelper)`。同一台机器上装了两个
helper，就是两个环境。同一 `(sshHost, sshHelper)` 不允许注册两次。

## 理由

- 判定与清理都以 helper 为锚点：删除环境要精确删掉远端那一行公钥和那个文件，
  而这天然按 helper 而不是按主机定位。
- 一台机器上装两个 helper 是使用者的能力，不是需要阻止的重复：不同工作区、
  不同用途可以各自独立。
- 以主机为单位会让“同一台机器上两套环境”变成结构上不可能，而这是一个正当需求。

## 后果

正面：删除一个环境不会影响同机另一个环境的登录能力；每个环境一把密钥，
`authorized_keys` 里每个环境一行，注释标记 `dsh-daemon:<id>` 精确匹配。

负面：同一台机器可能装多个 helper，远端会有冗余文件。接受这一点——那是使用者
的选择，且卸载脚本可以按环境逐个清理。

## 为什么不用 `(sshHost, sshUser)` 做键

同一台机器、不同用户可以有各自的 helper，那确实是两个环境。用户不是身份，
helper 路径才是。

## 被否决的替代方案

- **以主机为单位**：结构上禁止同机多环境，且删除时无法区分同机两个环境的凭据。
- **不设身份约束，允许重复**：两个环境共享一个 helper 文件，删一个会打断另一个。
