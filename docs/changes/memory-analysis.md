# 内存占用分析（2026-10-18）

生产单进程实测 RSS 1841 MB。本文记录实测数据与成因，全部数字来自
`/proc/<pid>/smaps`、V8 inspector 与受控对照实验，不是估算。

## 结论先行

内存由三块构成，其中只有第三块可以压缩：

| 构成 | 实测 | 性质 |
| --- | --- | --- |
| 加载 331 个插件的固定开销 | 656 MB | 启动即发生，与使用无关 |
| 打开一个大会话 | +700 MB | 会话数据本身，当前对话触发 |
| 长期运行的堆高水位 | +300～500 MB | V8 保留未归还，GC 可回收 |

**没有内存泄漏。** 连续采样 2 分钟 RSS 稳定在 1830～1850 MB，峰值 1905 MB。

## 一、固定开销 656 MB

全新实例、未连浏览器、未打开任何会话：

```
VmRSS              656 MB
heapUsed           278 MB   ← 活数据
heapTotal          289 MB   ← V8 已提交
```

`heapUsed` 278 MB 全部是加载插件的产物。规模来源：

```
dsh 核心包            305 个（磁盘 566 MB，JS 100 MB）
profile 装入包         59 个（JS 110 MB）
Loader 行组合计        359 行（核心 321 + 已装 38）
其中最大的三组：
  dsh-web-app         118 行
  dsh-base             97 行
  dsh-sdk-minimal      36 行
```

所以「一个进程 656 MB 起步」是 331 个插件挂载的直接结果，不是 dsh 内核本身。

## 二、会话数据 +700 MB（本次分析的关键）

受控实验：同一进程，打开本对话（当前会话）：

| 指标 | 打开前 | 打开后 | 增量 |
| --- | --- | --- | --- |
| RSS | 650 MB | 1350 MB | **+700 MB** |
| V8 堆段 | 170 MB | 623 MB | +453 MB |
| heapUsed | 278 MB | 431 MB | **+153 MB** |
| heapTotal | 289 MB | 597 MB | +308 MB |

会话文件本身：

```
压缩      12 MB   (session.v4.jsonl.zstd)
解压      42 MB   (18538 行)
最长单行  161 KB
```

**放大链路：42 MB 原始 JSON → 153 MB 活对象 → 700 MB RSS。**

- **3.6 倍**：JSON 解析成带类型、带校验的对象图。一条消息在磁盘上是一行 JSON，
  在内存里是 message 对象、content 块、工具调用记录、token 统计、渲染树节点等多层结构。
- **4.6 倍**：活对象 153 MB 到 RSS 700 MB 的差额，是 V8 为新老对象交替而保留的
  半空间，加上对象图造成的堆碎片。

## 三、GC 可回收的部分

对同一进程强制执行两轮全量 GC：

```
        RSS      heapTotal   heapUsed
GC 前  1445 MB    427 MB      270 MB
GC 后  1131 MB    276 MB      270 MB
```

`heapTotal` 降了 151 MB 而 `heapUsed` 几乎没动 —— 这部分是 V8 预留但闲置的空间，
不是活数据。它不会自动归还给操作系统，除非主动触发 GC 或达到堆上限。

## 四、为什么两进程反而更省

旧形态 1345 MB（edge 439 + web 906），单进程曾测到 1444 MB。原因不是内嵌变差，而是：

1. 内嵌后 `main` 一个进程同时承担面板与 harness，插件总数从 ~200 涨到 331。
2. 旧形态里 `edge` 只挂 daemon 一个插件（439 MB 主要是 Node 基础开销）。
3. 本次测量时我这个对话已经积累到 42 MB / 18538 行，旧形态没测过这种规模的会话。

因此「省 380 MB」的早期结论作废：**内嵌省的是一个进程和一套认证，不是内存。**

## 五、可压缩项（按收益排序）

| 措施 | 预计收益 | 代价 |
| --- | --- | --- |
| 精简挂载插件（关掉不用的） | 每 100 个插件约 85 MB | 功能取舍 |
| 长会话归档 / 分页加载 | 单会话最高 700 MB | 需改会话加载逻辑 |
| 定期主动 GC | 150～300 MB | 治标，需暴露触发点 |
| 限制 `--max-old-space-size` | 上限更早触发 GC | 过小会 OOM |

前两项是真实收益，后两项只是把同一块内存搬来搬去。

## 测量方法

```bash
# 进程内存构成
grep -E "VmRSS|RssAnon" /proc/<pid>/status
awk '/^Rss:/ {s+=$2} END {print s/1024" MB"}' /proc/<pid>/smaps

# V8 堆（需 --inspect 启动后经 CDP 求值）
process.memoryUsage()          # rss / heapTotal / heapUsed / external
HeapProfiler.collectGarbage    # 强制全量 GC
HeapProfiler.takeHeapSnapshot  # 快照后按类型与构造器聚合
```

注意：拍堆快照本身会短暂占用约 240 MB，测量时须避免把快照开销算进被测对象。
本文的 656 MB 基线取自从未拍过快照的实例。
