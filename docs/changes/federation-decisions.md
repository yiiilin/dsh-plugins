# 联邦设计 —— 已定决策清单

2026-10-18 的 12 轮设计审查结论。每条都是操作者明确选定的，
实现时以此为准；与之冲突的旧设计文档（`unified-entry-routing.md`）应视为作废。

## 形态

| # | 决定 |
| --- | --- |
| Q1 | 不做「两个 dsh 互相看见对方数据」的联邦读取；边端只贡献自己的界面 |
| Q15 | 走联邦，不是 SSH 环境 |
| Q28 | 边端装完整 dsh + 我们的插件，systemd 常驻 |
| Q41 | 主端与边端是同一个插件的两个角色，由 `role` 配置决定 |
| Q42 | 不再有 `local` / `ssh` 两种环境类型，只有「本机」与「联邦边端」 |
| Q47/Q56 | SSH 模式最终删除；先建联邦、验证、再删 |
| Q48 | 环境不再占本地端口，只有 id 与隧道连接状态 |
| Q59 | 边端的 56789 绑 `127.0.0.1`，隧道是唯一入口 |

## 传输

| # | 决定 |
| --- | --- |
| Q35 | 一个 WSS 连接承载全部流量，帧内多路复用 |
| Q53/Q54 | 隧道自建（约 150 行），复用 `entry.js` 已有的前缀/Host/upgrade 逻辑 |
| Q55 | 不做连接池，一边端一条连接 |
| Q50 | 指数退避重连，上限 60 秒，无限重试 |
| Q60 | 断线时环境标「离线」，不从列表移除 |

## 鉴权

| # | 决定 |
| --- | --- |
| Q36 | 每环境一个 token |
| Q61 | 支持 `?token=` 与 `Authorization: Bearer`，前者优先（WS 浏览器 API 不能设 header） |
| Q64 | token 反查环境身份，不需要 id 与 token 双因子（借自 Komari `IdentifyPrincipal`） |
| Q57/Q65 | 边端上报 hostname + machineId；主端按 token 找记录，有则复用 envId |
| Q30 | 主端不存边端密码，只有 token |

## 插件划分

| # | 决定 |
| --- | --- |
| Q52/Q66 | `web-daemon` 改名 `supervisor`，只做 systemd 单元与会话恢复 |
| Q46 | 隧道放 `daemon`（另有 Q53 讨论，最终仍在 daemon 内，因与 listener 强耦合） |
| Q39 | 主端可看边端技能/插件，可推送主端内容到边端 |
| Q43 | 读边端清单走隧道调它的 `/state`，不走 SSH |
| Q44 | 推送技能 = 复制目录（技能就是一个目录 + SKILL.md） |

## UI

## 仍然开放

- 主节点是否支持 TLS 终止在自身（当前依赖外部 nginx）
- 边端多实例（一台机器跑两个 dsh）是否需要支持
- 主节点的系统资源监控是否要聚合边端数据

## 术语

见 `GLOSSARY.md`。核心变化：「工作区」明确属于某台机器；「环境」不再由 profile 实现，
而是「一台机器上的一个 dsh 进程」。
