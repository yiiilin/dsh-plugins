# 联邦设计 —— 已定决策清单

2026-10-18 的 12 轮设计审查结论。每条都是操作者明确选定的，实现时以此为准。
与旧设计文档（`unified-entry-routing.md`）冲突时，以本文为准。

标注【已作废】的条目是设计转向后不再适用的早期决定，保留以说明演变，不参与实现。

## 核心需求（这条是全部设计的目的）

**在主节点上操作边端，体验要与操作本地 dsh 完全一致**：能看到工作区及其下的会话、
能看到会话记录、各类插件照常使用。（Q16）

实现方式：切换环境即整页跳到 `/<envId>/`，加载边端自己的完整界面。
不是「本地界面拼接远端数据」，而是「远端界面借本地入口呈现」。

## 传输

| # | 决定 |
| --- | --- |
| Q29 | 边端主动连主端（frp / 内网穿透方向），主端沿这条连接反向访问边端 |
| Q35 | 一条双向隧道承载全部流量。HTTP 请求主端接收 → 隧道转发 → 边端还原 → 响应回传 |
| Q30 | 主端验证边端（不是边端验证用户）；固定 token；因此主端不存任何边端密码 |
| Q36 | 每环境一个 token |
| Q53 | 隧道放在 `daemon` 内（不是独立插件）——它与 webserver 紧密相连 |
| Q54 | 自建，用 `ws` 加帧协议。评估过 localtunnel/cloudflared（拓扑对但不支持 WebSocket）、frp/rathole（独立进程） |
| Q55 | 不做连接池，一边端一条连接 |
| Q50 | 指数退避重连，上限 60 秒，无限重试 |
| Q60 | 断线时环境标「离线」，不从列表移除 |

### 修订后的顺序

原顺序把「删 SSH」放最后，与 Q56 冲突。按操作者的意思改为：

| 步 | 内容 |
| --- | --- |
| 0 | 删除 SSH 模式与 6.13 那个空环境 |
| 1 | 隧道（daemon 加 role/edge、帧协议、重连） |
| 2 | 边端接入（边端装 dsh + 配置） |
| 3 | 环境列表与切换 |
| 4 | 远端配置读取（`/state` 经隧道） |
| 5 | 同步与联邦工具 |
| 6 | `web-daemon` → `supervisor` 改名 |

## 仍然开放

- 主节点是否自己在进程内终止 TLS（当前依赖外部 nginx）
- 一台机器跑两个 dsh（多实例边端）是否需要支持
- 主节点是否聚合边端的系统资源监控

## 术语

见 `GLOSSARY.md`。「环境」= 一台机器上的一个 dsh 进程；「工作区」属于某台机器；
「主环境」是相对概念。
